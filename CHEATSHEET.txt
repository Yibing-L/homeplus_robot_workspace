--------------------------------------------------------------------------------
  0. ONE-TIME / EVERY-SHELL SETUP
--------------------------------------------------------------------------------
# Source ROS 2 + workspace overlay (do this in EVERY new terminal)
source /opt/ros/humble/setup.bash
source ~/homeplus_robot_workspace/install/setup.bash

# Optional: add to ~/.bashrc so it auto-loads
echo 'source /opt/ros/humble/setup.bash' >> ~/.bashrc
echo 'source ~/homeplus_robot_workspace/install/setup.bash' >> ~/.bashrc


--------------------------------------------------------------------------------
  1. BUILD
--------------------------------------------------------------------------------
cd ~/homeplus_robot_workspace

# Full build (all packages)
colcon build --symlink-install

# Build only one package (faster while iterating)
colcon build --packages-select homeplus_moveit_config --symlink-install
colcon build --packages-select homeplus_vision           --symlink-install
colcon build --packages-select homeplus_urdf_description --symlink-install
colcon build --packages-select homeplus_interfaces       --symlink-install

# Convenience: builds all four packages
bash scripts/build_e2e.sh

# Clean wipe
rm -rf build/ install/ log/

# After every build:
source install/setup.bash


--------------------------------------------------------------------------------
  2. RUN THE FULL SYSTEM (4 TERMINALS — recommended)
--------------------------------------------------------------------------------
Open 4 terminals. Run setup (section 0) in each. Then:

# --- Terminal 1: Robot TF + RealSense camera
cd ~/homeplus_robot_workspace
bash scripts/run_robot_tf.sh &
sleep 3
bash scripts/run_realsense.sh

# --- Terminal 2: GroundingDINO (object detection -> /gdino_pose_world)
cd ~/homeplus_robot_workspace
WORLD_FRAME=world bash scripts/run_dino.sh 1
# task_id arg: 1 = pick_up_coffee preset

# --- Terminal 3: MoveIt + gesture executor + Arduino bridge
cd ~/homeplus_robot_workspace
ros2 launch homeplus_moveit_config gesture_control.launch.py \
    arduino_port:=/dev/ttyACM0
# add use_octomap:=true to enable OctoMap collision avoidance

# --- Terminal 4: Gesture recognizer (vision -> /gesture_control/command)
cd ~/homeplus_robot_workspace
bash scripts/run_gesture.sh /absolute/path/to/checkpoint.pt /absolute/path/to/label_map.json

--------------------------------------------------------------------------------
# One-time install
sudo apt install tmux
pip install --user tmuxp

cd ~/homeplus_robot_workspace

GESTURE_CHECKPOINT=/abs/checkpoint.pt \
GESTURE_LABEL_MAP=/abs/label_map.json \

# In-session keybindings (prefix is Ctrl-b):
#   Ctrl-b  arrows   move between panes
#   Ctrl-b  z        zoom current pane fullscreen (toggle)
#   Ctrl-b  [        scrollback mode (q to exit, / to search)
#   Ctrl-b  d        detach (system keeps running)

# Session management (tmuxp has no `kill` — use plain tmux):
tmux ls                           # list running sessions
tmux attach -t homeplus           # reattach after detaching
tmux kill-session -t homeplus     # tear down the session
tmux kill-server                  # kill ALL tmux sessions

# Restart one component: click into its pane, Ctrl-C, up-arrow, Enter.
# If a pane's process crashed, it stays open (remain-on-exit: on) so you can
# read the error. Press Enter to respawn it.

--------------------------------------------------------------------------------
  6b. RVIZ — MOTION PLANNING / OCTOMAP VIEWING
--------------------------------------------------------------------------------
RViz auto-launches when you run gesture_control.launch.py or moveit.launch.py.
It comes up loaded with config/moveit.rviz (already configured for planning).

If you don't see the planning panel:
  Top menu: Panels -> Add New Panel -> MotionPlanning  (under moveit_ros_visualization)

Key displays in the left "Displays" tree (toggle visibility with their checkboxes):
  RobotModel               current robot pose
  PlanningScene            collision world MoveIt sees
  MotionPlanning           the planning panel widget
  TF                       transform frames (turn off if cluttered)
  Trajectory               the planned path animation
  MarkerArray              detection markers (DINO etc.)
  OccupancyMap / OctoMap   voxel grid (only when use_octomap:=true)

How to PLAN A MOTION manually in RViz:
  1. In Displays, expand "MotionPlanning" -> Planning Request:
       - Planning Group: arm   (or whatever group is set in homeplus.srdf)
  2. Drag the orange interactive ball (end-effector goal marker) to where you
     want the gripper to go. The robot ghost shows the goal pose.
  3. Bottom panel "Motion Planning" -> "Planning" tab:
       Plan          compute a trajectory (does NOT execute)
       Execute       send the planned trajectory to the controller
       Plan & Execute  do both
  4. If "Plan" fails, check the "Status:" line at the bottom — usually
     "No motion plan found" (try a closer goal) or a collision message.

Useful checkboxes inside MotionPlanning panel:
  Allow Approximate IK Solutions    relax IK if exact pose unreachable
  Allow Replanning                  retry on failure
  Use Cartesian Path                straight-line interpolation
  Show Workspace                    visualize planning bounds

To view OctoMap collisions in RViz:
  ros2 launch homeplus_moveit_config gesture_control.launch.py use_octomap:=true
  In RViz: Add -> By topic -> /octomap_full -> OccupancyGrid (or OcTree)
  Alternative pre-built config:
       rviz2 -d homeplus_moveit_config/config/octomap.rviz

To save a tweaked RViz layout:
  File -> Save Config As ...   (overwrite moveit.rviz to make it persistent)

--------------------------------------------------------------------------------
  7b. FAKE-A-COFFEE-PICK END-TO-END (watch planning + motion in RViz)
--------------------------------------------------------------------------------
This lets you watch a full pick_up_coffee sequence in RViz WITHOUT a camera,
gesture model, or coffee cup — fake both the detection AND the gesture command.

PREP (one time, in RViz):
  In the Displays tree, expand:  MotionPlanning -> Planned Path
  Make sure these are ON (checkboxes):
      Show Robot Visual      (translucent ghost shows the planned path)
      Show Trail             (leaves the path visible)
      Loop Animation         (replay the animation)
  Trajectory Topic:  /display_planned_path   (default; should already be set)
  Also make sure these top-level Displays are ON:
      RobotModel             live robot (follows controller as it executes)
      PlanningScene          collision world

REQUIRED RUNNING:
  At minimum the MoveIt stack + gesture executor must be up:
      ros2 launch homeplus_moveit_config gesture_control.launch.py \
          launch_moveit:=true run_arduino:=false
  (run_arduino:=false avoids needing /dev/ttyACM0 plugged in)
  TF must also be publishing — easiest is to also start scripts/run_robot_tf.sh
  Or just bring up the whole tmux session (T1 + T3 panes are enough).

STEP 1 — fake the coffee detection (sequence reads /gdino_pose_world):
  ros2 topic pub --rate 5 /gdino_pose_world geometry_msgs/msg/PoseStamped \
    "{header: {frame_id: 'world'},
      pose: {position: {x: 0.4, y: 0.0, z: 0.3},
             orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}}"
  # leave this running in its own terminal — the executor needs an active stream
  # adjust x/y/z to a pose that is reachable for the arm

STEP 2 — fire the fake gesture (in another terminal):
  ros2 topic pub --once /gesture_control/command \
    homeplus_interfaces/msg/GestureCommand \
    "{gesture_id: 1, gesture_label: 'fake_coffee', confidence: 0.99,
      command_name: 'pick_up_coffee', command_type: 'sequence'}"

STEP 3 — approve each displayed plan after inspecting it in RViz:
  ros2 topic pub --once /gesture_control/approve_planned_path \
    std_msgs/msg/Bool "{data: true}"
  # publish data: false to reject the current path

WHAT YOU SHOULD SEE IN RVIZ:
  1. The translucent ghost robot animates each waypoint of the sequence
     (approach, descend, grasp, lift, retreat) — that is /display_planned_path.
  2. The opaque RobotModel then physically moves to follow each plan,
     because the executor sends the trajectory to the controllers.
  3. Console of the gesture_motion_executor pane prints:
       "  approach: resolved target -> [0.400, 0.000, 0.300]"
       "  Plan succeeded for arm group"
       "  Executing trajectory ..."

WATCH THE TRAJECTORIES TOPIC DIRECTLY:
  ros2 topic echo /display_planned_path moveit_msgs/msg/DisplayTrajectory --no-arr
  ros2 topic hz   /display_planned_path

REPLAY a saved trajectory in RViz:
  ros2 run homeplus_moveit_config replay_trajectory.py
  (look in trajectory_logs/ for what gets recorded)

TROUBLESHOOTING:
  Nothing happens after STEP 2:
      Check executor saw the command:  ros2 topic echo /gesture_control/command
      Check it's seeing the fake pose: ros2 topic echo /gdino_pose_world
      Confirm move_group is up:        ros2 node list | grep move_group
  Plan fails ("No motion plan found"):
      Pick a more reachable x/y/z; default arm reach is roughly within 0.5m
  Ghost moves but live robot doesn't:
      Trajectory is planning OK but execution failed — check controller status:
          ros2 control list_controllers
      Or set enable_moveit_planning:=false on the launch to bypass MoveIt exec.

--------------------------------------------------------------------------------
 11. TYPICAL FAILURES & FIRST CHECKS
--------------------------------------------------------------------------------
RViz black / no robot         source install/setup.bash; rebuild urdf pkg
"package not found"           you forgot `source install/setup.bash`
camera frames missing         `ros2 topic hz /camera/camera/color/image_raw`
no /gdino_pose_world          DINO needs a valid TF target frame (use WORLD_FRAME=world for base_arm planning) and camera publishing
gripper not reacting          `ros2 topic echo /arduino/ack`; check /dev/ttyACM0 perms
TF errors                     `ros2 run tf2_ros tf2_echo world camera_link`
MoveIt plan fails             toggle use_octomap off to isolate; check /joint_states
